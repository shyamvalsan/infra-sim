Claim & teardown

These are a checklist, not buttons. Whether Netdata Cloud's API can automate node removal and Space deletion is still an open question in the spec, and a button that silently does nothing is worse than a checklist that tells the truth.

  • Create a fresh Space named <Prospect> (Simulated Demo) — one per prospect, never reused.
  • Claim this agent to that Space. One claim covers the whole fleet; every vnode appears automatically.
  • Confirm every node carries the simulated=true host label. The runtime applies it and an environment file cannot override it.
  • Only one instance of a base may be claimed at a time — GUIDs must be unique across the infrastructure. Re-skin and re-claim; never clone.
  • At teardown: disarm scenarios, stop the plugin process (removing the file is not enough), remove now-offline nodes, delete the Space.
  • Archive environment.yaml, the generator spec, the seed and the scenario manifests. Those four replay the identical world.
