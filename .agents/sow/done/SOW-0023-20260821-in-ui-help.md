# SOW-0023 - In-UI help and onboarding

## Status

Status: completed

`completed` is the successful terminal status. `done` is a directory name, not a status value.

Sub-state: delivered - Help tab, first-run banner, gates and live checks green; closing.

## Requirements

### Purpose

A person opening the console for the first time — an SE preparing a demo, or anyone in Netdata on a hosted box — can learn what this is, what the workflow is, and what every setting does, without leaving the page. Third of four hosting-prep SOWs.

### User Request

"UI needs to be simple and intuitive, with help inbuilt into it on how to use, what different settings are for etc. (inside a help section)."

### Assistant Understanding

Facts:

- The UI has two tabs (Build, Run) and 17+ `data-tip` tooltips that explain *fields*, but no help section, no workflow overview, and no concept documentation in-page. The knowledge exists in README/QUICKSTART/operating.md, all outside the console.
- The console now serves hosted users (SOW-0021/0022): owners, budgets, TTL/pin, queue positions, a token prompt — none of which have in-UI explanation beyond fragments.
- `showTab()` toggles a hard-coded tab list; adding a third tab is a two-line change. The UI ships embedded in the binary (`include_str!`), so help content ships with every console and works on a hosted box with no network.
- Docs live on GitHub; a hosted box's users can reach them, but the essentials must not depend on it.

Inferences:

- A **Help tab** (Build | Run | Help) is the structure: always one click away, no modal framework needed, consistent with the existing chrome.
- A **first-run banner** on the Build tab (dismissed via `localStorage`, so dismissal persists per browser) gives the 3-step path without nagging returning users.
- Help copy must be **consequence-aware** (what a choice costs: name is permanent, teardown archives, ML needs hours), not just descriptive — the tooltips already describe; the help section explains.

Unknowns:

- None blocking.

## Acceptance Criteria

- A Help tab exists beside Build and Run, self-contained in the page (works offline-from-GitHub on a hosted console), covering: what the product is (the one hard rule), the five-step workflow, the key concepts (identity/GUIDs, warm-up, scenarios and ground truth, labels, exporters, logs/traces), shared-host rules (token, owner, budgets, TTL/pin, queue), the top gotchas, and links to the three docs for depth.
- A dismissible first-run banner appears on Build for a fresh browser and stays dismissed after that; it names the three steps and points at Help.
- Existing behavior unchanged: all prior gates green, no handler/route changes.
- Live check: the served page contains the help content; JS syntax clean.
